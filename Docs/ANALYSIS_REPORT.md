# Отчёт анализа проекта «3авхоз.рф»

## 1. Обзор проекта

Проект представляет собой SaaS‑решение для инвентаризации основных средств с использованием QR‑кодов.  
Стек: **Frontend** – Vite, React, TypeScript, Tailwind, Radix UI; **Backend** – Node.js, Express, Prisma, PostgreSQL (Supabase); **Shared** – общие типы TypeScript.

### 2.1. Выявленные небольшие несоответствия

1. **Отчёт в UI** – кнопка «Скачать отчёт» в `Demo.tsx` пока не привязана к реальному API (`GET /api/reports/:id`). Фронтенд ожидает эндпоинт, но в бекенде он не реализован (только заглушка).  
2. **Rate limiting** – в документации (README, чек‑лист) указано добавить rate‑limiting, но в коде отсутствует middleware `express-rate-limit`.  
3. **HTTPS / CORS production** – в `backend/src/index.ts` CORS настроен, но переключение на production‑домены требует ручного изменения; автоматической проверки нет.  
4. **Тесты** – в репозитории нет тестов, хотя в чек‑листе указано их добавить.  

## 3. Рекомендации

| Приоритет | Действие | Описание |
|-----------|----------|----------|
| **Высокий** | Реализовать эндпоинт `GET /api/reports/:id` и подключить его к кнопке «Скачать отчёт» в `Demo.tsx`. | Позволит пользователям получать готовый отчёт в формате PDF/Excel. |
| **Высокий** | Добавить middleware `express-rate-limit` в `backend/src/index.ts` (лимит 100 запросов/минуту на IP). | Уменьшит риск DoS‑атак и соответствует чек‑листу комплаенса. |
| **Средний** | Настроить автоматическое переключение CORS‑origin в зависимости от `NODE_ENV`. | Упростит деплой в production и уменьшит риск утечки. |
| **Средний** | Добавить unit‑ и integration‑тесты для ключевых роутов (auth, import, gdpr, reports). | Повысит надёжность и покрытие требований к качеству. |
| **Низкий** | Обновить UI‑компонент «Скачать отчёт», добавить индикатор загрузки и обработку ошибок. | Улучшит UX. |
| **Низкий** | Внести в `README.md` ссылку на новый файл `ANALYSIS_REPORT.md` для полной прозрачности. | Упростит навигацию. |
