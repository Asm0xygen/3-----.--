## 1. Frontend

### `frontend/src/App.tsx`

- **Severity**: INFO
- **Наблюдения**: Простая обёртка, использует все компоненты. Критических уязвимостей нет.
- **Рекомендации**: Добавить CSP и X‑Frame‑Options через Vite.

### `frontend/src/main.tsx`

- **Severity**: INFO
- **Наблюдения**: Точка входа, стандартная конфигурация Vite.
- **Рекомендации**: Использовать `import.meta.env` для конфигураций.

### `frontend/src/index.css`

- **Severity**: INFO
- **Наблюдения**: Базовые стили Tailwind, проблем безопасности нет.
- **Рекомендации**: Нет.

### `frontend/src/components/Header.tsx`

- **Severity**: MEDIUM
- **Наблюдения**: Отсутствуют HTTP‑заголовки безопасности (Content‑Security‑Policy, X‑Content‑Type‑Options).
- **Рекомендации**: Настроить заголовки на уровне бэкенда или через Vite‑плагин.

### `frontend/src/components/Hero.tsx`

- **Severity**: INFO
- **Наблюдения**: Генерация QR‑кодов на клиенте, без серверной валидации.
- **Рекомендации**: Ограничить длину данных, валидировать на сервере.

### `frontend/src/components/Features.tsx`

- **Severity**: INFO
- **Наблюдения**: Описание функций, без логики ввода.
- **Рекомендации**: Нет.

### `frontend/src/components/Demo.tsx`

- **Severity**: HIGH
- **Наблюдения**: Пользовательский ввод (`scanInput`) без валидации формата номера инвентаря, потенциальный XSS при выводе.
- **Рекомендации**: Экранировать ввод, добавить проверку regex, например `/^ОС-\d{4}$/`.

### `frontend/src/components/BeforeAfter.tsx`

- **Severity**: INFO
- **Наблюдения**: Статический текст, без интерактивности.
- **Рекомендации**: Нет.

### `frontend/src/components/CTA.tsx`

- **Severity**: INFO
- **Наблюдения**: Кнопки без особых рисков.
- **Рекомендации**: Нет.

### `frontend/src/components/Footer.tsx`

- **Severity**: INFO
- **Наблюдения**: Статический футер.
- **Рекомендации**: Нет.

## 2. Backend

### `backend/src/index.ts`

- **Severity**: HIGH
- **Наблюдения**: CORS разрешён `*` в небезопасных средах, отсутствие rate‑limiting, нет security‑headers (`helmet`).
- **Рекомендации**: Ограничить CORS конкретным доменом, добавить `express-rate-limit` и `helmet`.

### `backend/src/db/index.ts`

- **Severity**: MEDIUM
- **Наблюдения**: Используются типы `any` в адаптере Prisma, возможны несоответствия типов.
- **Рекомендации**: Заменить `any` на строгие TypeScript‑типы.

### `backend/src/db/mock.ts`

- **Severity**: HIGH
- **Наблюдения**: Жёстко закодированные демо‑учётные данные (email и хеш пароля), могут попасть в продакшн.
- **Рекомендации**: Удалять демо‑аккаунты из сборок, использовать реальные данные только в тестах.

### `backend/src/routes/auth.ts`

- **Severity**: CRITICAL
- **Наблюдения**:
  1. Нет блокировки после неудачных попыток → уязвимость к brute‑force.
  2. `JWT_SECRET` берётся из env без проверки; при отсутствии токен не генерируется.
  3. Нет требований к сложности пароля.
  4. Отсутствует ограничение количества запросов.
- **Рекомендации**:
  1. Добавить `express-rate-limit` для `/login` и `/register`.
  2. Проверять наличие и длину `JWT_SECRET` (не менее 256 бит).
  3. Ввести политику сложности пароля.
  4. Реализовать блокировку аккаунта после 5 неудачных попыток.

### `backend/src/routes/assets.ts`

- **Severity**: LOW
- **Наблюдения**: GET‑эндпоинт возвращает все активы без пагинации → риск DoS при большом объёме.
- **Рекомендации**: Ввести пагинацию и лимит результатов.

### `backend/src/routes/import.ts`

- **Severity**: HIGH
- **Наблюдения**:
  1. Нет ограничения размера загружаемого файла.
  2. Нет проверки обязательных колонок CSV/Excel.
  3. Данные из файла передаются в Prisma без дополнительной валидации.
  4. Эндпоинт генерации QR‑кодов не имеет rate‑limiting.
- **Рекомендации**:
  1. Ограничить размер загрузки (например 5 МБ).
  2. Валидировать наличие обязательных полей и типы данных.
  3. Добавить серверную валидацию полей активов.
  4. Ограничить частоту запросов к `/generate-qr`.

### `backend/src/routes/inventory.ts`

- **Severity**: MEDIUM
- **Наблюдения**: Эндпоинт `/scan` доступен без аутентификации.
- **Рекомендации**: Защитить все маршруты аутентификацией и проверкой прав доступа.

### `backend/src/routes/reports.ts`

- **Severity**: LOW
- **Наблюдения**: Возвращаются внутренние ID без фильтрации по пользователю.
- **Рекомендации**: Ограничить доступ ролями, добавить пагинацию.

### `backend/src/routes/gdpr.ts`

- **Severity**: CRITICAL
- **Наблюдения**:
  1. `requireAuth` не проверяет JWT – любой может вызвать эндпоинты.
  2. Возвращаются избыточные метаданные (IP, user‑agent).
  3. Нет ограничения частоты запросов.
- **Рекомендации**:
  1. Реализовать полноценную проверку JWT (подпись, срок действия).
  2. Ограничить возвращаемые поля только необходимыми персональными данными.
  3. Добавить rate‑limiting и аудит запросов.

## 3. Shared

- **Severity**: INFO
- **Наблюдения**: Интерфейсы TypeScript описаны, но поля `status` объявлены как `string` вместо литеральных типов.
- **Рекомендации**: Использовать точные типы (`'active' | 'found' | 'missing'` и т.д.) для повышения типобезопасности.

## 4. Конфигурация

- **Severity**: MEDIUM
- **Наблюдения**: `.env.example` содержит шаблоны, но нет комментариев о требуемой длине `JWT_SECRET` и формате `DATABASE_URL`. Риск случайного коммита реальных секретов.
- **Рекомендации**: Добавить комментарии, внедрить pre‑commit hook, проверяющий отсутствие реальных секретов.

## 5. Общая архитектура

- **Severity**: INFO
- **Наблюдения**: Разделение слоёв (routes, db, shared) адекватно, но многие места используют `any`, снижают типобезопасность.
- **Рекомендации**: Заменить `any` на строгие типы, централизовать обработку ошибок, внедрить структурированное логирование, добавить юнит‑тесты для критических путей.
